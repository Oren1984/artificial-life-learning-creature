## What the video shows, and how it was made

The video is a screen capture of the actual application (the same Docker image
that `docker compose up --build` produces), driven through its normal UI by a
script. Nothing in the application was changed for it.

1. The untrained creature on held-out layout 9000.
2. A full default training run started from the UI: population 40,
   50 generations, training seed 0.
3. Baseline and trained creature side by side on the same held-out layout.
4. The measured-evidence table, then the limitations.

Things worth knowing:

- **Captions and title cards are overlays** drawn on top of the page by the
  recording script. They are not part of the application.
- **Every number in a caption is read from the recorded run's stored
  evaluation**, not typed into the script.
- **The training segment is a time-lapse.** The run is real and uncut, but it
  is played about 3× faster than real time and labelled "Training · time-lapse"
  on screen. Everything else plays at real speed.
- **Training took 91 seconds in this take**, not the ~40 seconds quoted
  elsewhere, because the machine was busy and was also capturing the screen.
  The caption states the 91 seconds that were actually measured.
- **The recorded run reproduces the reference run.** It was made on a separate
  throwaway instance, so its run id (in `recording.json`) is not the reference
  run's, but its per-generation metrics and its evaluation were compared with
  [`../results/`](../results/) and are identical.
- The video states the same conclusions and limitations as
  [`../experimental-results.md`](../experimental-results.md): food-seeking was
  learned; the creature only matches a one-line greedy rule; hazard avoidance
  was not shown.

## Music

The background music is an original ambient pad generated by
`source/make_music.py` using only NumPy (sine tones, a fixed random seed). No
samples, loops or third-party recordings are used, so there is no third-party
licence and no attribution is required. It is covered by the same terms as the
rest of this repository.

## Rebuilding

Requires Node with the frontend dependencies installed, Google Chrome, Python
with NumPy, and `ffmpeg` on the PATH.

```bash
# 1. A fresh instance with no stored runs (no volume, so nothing is left behind)
docker run -d --rm --name creature-demo -p 127.0.0.1:8091:8080 learning-creature:local

# 2. Record (about two and a half minutes)
cd frontend
BASE_URL=http://localhost:8091 OUT_DIR=/path/to/work node ../docs/media/source/record-demo.mjs

# 3. Assemble
cd ..
python docs/media/source/build_video.py /path/to/work
docker stop creature-demo
```

The captured frames (a few hundred MB of JPEGs) stay in the work directory and
are not kept in the repository. A new take will differ slightly in timing, and
its training duration depends on the machine.
